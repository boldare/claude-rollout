Web UI

lib/server.mjs · lib/control.mjs · ui/

rollout ui serves a local web page over every rollout on your machine. It shows what the driver and its agents are doing, live, and it sends the same commands as the CLI. It reads files only and never calls GitHub.

What it is #

The UI has two halves.

  • A view. It reads the files in each rollout directory: manifest.yaml, ledger.json, events.jsonl, heartbeat, driver.lock, the briefs and the agent transcripts in logs/. It builds its tables with the same model as rollout status (lib/view.mjs), so the CLI and the UI never disagree.
  • A remote control. Pause, resume, unhalt, retry, note, hold and release become files in the rollout's inbox/, exactly the files the CLI writes. Stop and start act on the driver process itself.

It never calls GitHub or git. Stopped and finished rollouts work too, and watching costs no API calls. What you see about GitHub, such as a PR number or the gate's reading of the merge state, is what the driver recorded on its last tick.

The UI is not the driver. Closing the page or stopping rollout ui changes nothing about a running rollout, and a driver runs fine without the UI.

Starting it #

Start it in a terminal of your own. It runs until Ctrl C.

$ node $R ui
rollout ui: http://127.0.0.1:53817/#t=VGhpcyBpcyBhIHNhbXBsZSB0b2tlbiwgbm90IHJlYWw (Ctrl-C stops it)
flag default what it does
--root ROOT $ROLLOUT_ROOT, else ~/.rollouts The directory to list. Every entry in it with a manifest.yaml is a rollout. An empty ROLLOUT_ROOT counts as unset.
--port N a random free port A fixed port from 0 to 65535. The server listens on 127.0.0.1 only, whatever the port.
--no-open off Prints the URL without opening a browser. Without it, the URL opens with open on macOS and xdg-open on Linux.
--read-only off Turns every control off. See Read-only mode.
  • The printed URL carries an access token after #t=. Open that exact URL. The token lives only in the server's memory, so a restart of rollout ui prints a new one and old tabs stop working.
  • A rollout's name is its directory name. It must start with a letter, a digit or _ and hold only letters, digits, _, . and -, with no ... The sibling <name>.worktrees directory has no manifest, so it never shows up.
  • Agents cannot start the UI. Every agent runs with ROLLOUT_ROLE set, and the CLI refuses ui for them because the URL carries the token.

How it works #

rollout ui is a small node:http server in lib/server.mjs. The page is plain HTML, CSS and ES modules from ui/, with no build step and no framework.

The token

  • The server makes a random 32-byte token when it starts, prints it once in the URL and keeps it only in memory.
  • The token sits in the URL fragment, after #. Browsers never send the fragment to a server, so it never shows up in a request line or a log.
  • The page reads the token from the fragment and sends it as Authorization: Bearer <token> on every /api call. The server compares it in constant time. The page itself and its scripts load without a token.
  • The whole view state lives in the fragment next to the token: the rollout, the view, the PR, the tab and the filters. A reload, a bookmark or a link opened in a new tab lands on the same screen.

Live updates

  • An open rollout follows one Server-Sent Events stream, GET /api/rollouts/<name>/stream. On connect it sends the whole state and every event so far. After that it pushes a new state and only the new events.
  • The server watches the rollout directory with fs.watch, debounced by 250 ms, and polls it every 5 s. It pushes when the size or mtime of manifest.yaml, ledger.json, events.jsonl, heartbeat or driver.lock changes, or when the driver's process appears or dies. The poll catches a driver killed hard, which changes no file.
  • The stream sends a ping every 20 s. The page reads it with fetch, because EventSource cannot send the token header. After 45 s without a byte it reconnects, waiting 1 s at first and up to 30 s.
  • The transcript of a running agent is fetched every 3 s while its latest page is open. The rollout list refreshes every 5 s.
  • The page redraws every 30 s, so times like 4m ago stay true.

Commands

A control posts JSON to POST /api/rollouts/<name>/commands, for example {"cmd":"hold","id":"P2"}. The server checks it before it acts: a known command, a PR id from the manifest, a note with text, a JSON body of at most 64 KiB.

  • Inbox commands. Pause, resume, unhalt, retry, note, hold and release are written to inbox/ through a temporary file and a rename, so the driver never reads half a command. A running driver watches the inbox and applies the command at the start of its next tick. When it sleeps between ticks, that is about half a second later. With no driver running, the file waits for the next start.
  • Stop. The server sends SIGTERM to the pid in driver.lock. The driver stops its agents, saves and exits, and the next start resumes their sessions. A second stop is refused while the first one is pending, because a second SIGTERM makes the driver exit at once, without waiting for its agents.
  • Start. Refused while a driver holds the lock. Otherwise the server spawns node bin/rollout.mjs run --dir <dir>, with --dry-run when you tick the box. It runs detached, under /usr/bin/caffeinate -is on macOS when that exists, and its output is appended to driver.log in the rollout directory. It uses the copy of the skill that serves the UI. caffeinate keeps a Mac awake only on AC power with the lid open, so on battery the answer carries a warning.

The answer shows as a notice under the header for 15 s: hold P2 queued., with It applies when the driver starts. when no driver runs, Stopping the driver (pid 48213). or Starting the driver. Its output goes to …/driver.log. On battery the start notice ends with On battery: caffeinate cannot keep this Mac awake, keep the lid open or plug in.

  • state is the ledger state, in the colours of the PR lifecycle. A held badge marks a held PR, and a mono badge names the agent run in progress.
  • GitHub links to the PR once the implementer opened it.
  • deps lists the dependencies with their own state.
  • attempts b/i/f/v counts brief, implement, fix and verify attempts, against the caps in policy.attempts. A PASS sets the verify count back to zero, and a run that did no work gives its attempt back.
  • info is the most useful line the ledger has: the gate's action and reasons, the question of a blocked PR, the reason of a fix, the last error, or the merge commit. It starts with approved; or held; when that applies.

Timeline

One lane per PR, one bar per agent run, coloured by role. Gaps between bars are time spent waiting: for CI, a review or the next tick. Click a bar to open that run's transcript.

briefimplementfixverifydelegate
  • A brief shows as two bars, the writer and then the reviewer.
  • A hatched bar is an interrupted run, a red edge a failed one, and a dashed outline a run still going.
  • Markers show the moments between runs: a green dot for a READY claim, a grey diamond for a rebase, an orange dot for review feedback and a purple diamond for the merge.
  • A dashed vertical line is a driver restart. The run it cut is interrupted, and the next run resumes it.

Transcripts

A transcript is the agent's logs/<run>.jsonl, read and laid out for people.

run role effort start duration cost result denials error
P2-01-brief-write brief write xhigh 10:25 7m $1.30 BRIEF 0
P2-01-brief-review brief review xhigh 10:32 8m $1.45 BRIEF 0
P2-01-implement implement high 10:41 - ≈$1.12 est. interrupted -
P2-01-fix fix high 11:33 29m $5.10 READY 0
P2-02-verify verify high 12:04 21m $1.84 PASS 0
  • The header names the run, role, effort and status, the model, the number of items and the log size. A finished run adds its outcome, cost, duration, turns and denials. A run without a result shows its token usage per model and the cost estimate instead.
  • The items follow in order: the agent's text, each tool call with its command and a collapsible input, and each tool result, collapsed to its first line. A result the guard refused carries a guard refused badge and starts open.
  • Text over 10,000 characters is cut, with a note that the full text is in the log file.
  • The agent's final report ends the transcript as formatted JSON.
  • Pages hold 200 items, with first, previous, next and latest links. A running run opens on its latest page, is fetched again every 3 s, and the page sticks to the bottom while you are there.

Controls #

The rollout controls sit on the right of the header, the PR controls on the PR page. Each one shows only when it makes sense, and the ones that are hard to undo ask first. In every confirmation Cancel has the focus, so Enter never confirms by accident. The Note dialog puts the focus in its text box.

control where and when asks first what it does
Pause Header, while not paused. no Queues pause. The driver starts no runs and merges nothing. Running agents finish their step.
Resume Header, in place of Pause while paused. no Queues resume. Also the way out of a pause the driver made itself after an account limit.
Unhalt Header, while the rollout is halted. yes, with the halt's reason Queues unhalt. Clears the halt after a red base branch, so the driver merges again.
Stop Header, while a driver runs. Drawn in red. yes: Its agents stop too. The next start resumes their sessions. SIGTERM to the driver in driver.lock, like rollout stop. Refused while a stop is already pending.
Start Header, while no driver runs. The only control before a rollout's first run. yes, with a dry run box Starts a detached rollout run, with --dry-run when ticked, and appends its output to driver.log.
Hold PR page, while the PR is not held and not merged. no Queues hold. No new runs, rebases, ready notices or merges for this PR. A running agent finishes its step.
Release PR page, in place of Hold while held. no Queues release, which lifts the hold.
Note PR page, until the PR is merged. a text box, Send stays off until you type Queues note with your text. What it does depends on the PR's state. For a verified or ready_claimed PR the dialog warns that the PR goes back to the implementer and loses its verification.
Retry PR page, for an escalated, blocked or interrupted PR. yes: Its attempts start from zero. Queues retry, which resets the attempt counters and lets the PR run again.

What the UI does not do #

  • Approve. Approval stays a GitHub review or rollout approve. The server rejects an approve command, so nothing that can reach the page can approve a merge.
  • Start a subset. Start has no --only. Run rollout run --only P1,P2 in a terminal for that.
  • Preflight, status and card stay in the CLI. The board and the PR page show most of the same facts as status and card, but not the implementer's report.
  • Edit the manifest. Edit manifest.yaml in your editor. The driver reloads it on its next tick.

Read-only mode #

rollout ui --read-only is the UI for watching only. The terminal says read-only: the controls are disabled, the header carries a read-only badge, and no control is drawn.

The server enforces it too: it answers every command with 403 read-only, whatever the page sends. The page also treats a state without the flag as read-only, so a mismatch fails closed.

Troubleshooting #

Open the URL that rollout ui printed…
The page has no token, or the server no longer knows it (401). Open the URL from the terminal again. After a restart of rollout ui that is a new URL.
reconnecting to the stream…
The stream dropped or went silent for 45 s. The page retries on its own. If it stays, check that rollout ui still runs.
An amber heartbeat
The driver has not beaten for over 5 minutes. It may be stuck in a long git or GitHub call, or the machine slept. Look at the terminal that runs it, or at driver.log when the UI started it.
stopped, but work is left
No driver holds the lock. Press Start, or run rollout run in a terminal. Agents resume their sessions.
No rollouts in …
The root has no directory with a manifest.yaml. Check --root and ROLLOUT_ROOT.
unknown rollout
The rollout directory was renamed or lost its manifest while the page was open. Go back to the list.

Security in short #

  • The server listens on 127.0.0.1 only.
  • It checks Host on every request and Origin on every write, so another web page cannot reach it through DNS rebinding or a cross-site form.
  • Every API call needs the token. It stops a plain curl from another process, not code that can read your terminal or your browser history.
  • A strict Content Security Policy allows only the page's own files: no inline scripts or styles, no framing. The page builds every element with text, never HTML, because titles, verdicts and transcripts are untrusted agent output.

The details and their limits are on Security.
