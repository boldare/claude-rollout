Manifest

lib/manifest.mjs · examples/manifest.yaml

A rollout is one directory with one manifest.yaml. It names the repository, the PRs and their order, and the rules the driver enforces. The driver validates it when it loads it and again every time the file changes.

An annotated example #

This is examples/manifest.yaml with a few more comments. Copy it to ~/.rollouts/<name>/manifest.yaml and adapt it. Only the fields marked required in the tables below must be there. 

rollout: my-lib-1.2.0            # PRs get the label rollout:my-lib-1.2.0
model: opus                      # every agent role uses this model
# claudeBin: ~/tools/claude      # default: claude from PATH

repo:
  path: ~/code/my-lib            # your local clone
  github: my-org/my-lib
  base: main
  public: true                   # false for a private repo
  pathPrepend: []                # tool directories that go first on PATH
  # runs in every new worktree
  install: pnpm install --frozen-lockfile
  # check run names, as globs
  requiredChecks: ['test*', 'lint']
  # the bot account's token
  agentToken: ~/.config/rollout/agent-gh-token
  maintainers: [my-github-login]
  merge: { method: squash, admin: auto }
  neverMerge:                    # the release PR
    branches: ['changeset-release/*']
    titles: ['chore: version packages', 'chore: version packages (next)']
  forbid:                        # paths no PR may touch
    - '**/CHANGELOG.md'
    - .changeset/config.json
    - .github/workflows/release.yml
  # terms that must never appear
  denylist: [acme-client, /Users/]
  verify:
    common:                      # the recipe the implementer and the verifier run
      - pnpm install --frozen-lockfile
      - pnpm build
      - pnpm test
      - pnpm lint:fix            # the verifier's copy drops commands that rewrite files
      - pnpm lint && pnpm format:check

briefing:                        # only needed when the driver writes briefs
  sources:
    - title: Plan (authoritative)
      path: ~/.rollouts/my-lib-1.2.0/plan.md
      kind: markdown

policy:
  concurrency: 3
  merge: manual                  # the driver says "ready", you merge on GitHub
  approval: github
  maxBump: minor
  attempts: { implement: 2, fix: 4, verify: 3 }
  timeouts: { implement: 240, fix: 120, verify: 90 }

prs:
  - id: P1
    branch: feat/config-loader
    title: 'feat: config loader'
    brief: briefs/P1.md          # written by the driver when it does not exist
    deps: []
    priority: 10
    effort: { implement: xhigh, verify: xhigh }
    changeset: minor

  - id: P2
    branch: feat/cli-flags
    title: 'feat: cli flags'
    brief: briefs/P2.md
    deps: [P1]                   # starts once P1 has merged
    priority: 5
    effort: { implement: high, verify: high }
    changeset: minor
    allowWorkflows: true         # this PR adds a CI step

Paths expand a leading ~. Globs follow lib/glob.mjs: * stays inside one path segment, ** spans directories and ? is one character other than /.

Top level #

field type default required meaning
rollout string – yes The rollout's name. Every PR gets the label rollout:<name>, which the driver creates when it starts and the gate requires.
model string opus no The model for every agent role: brief writer and reviewer, implementer, fixer and verifier. It is passed as --model.
claudeBin path claude no The Claude Code binary. The default finds claude on PATH, with repo.pathPrepend first.
repo object – yes The repository and its rules. See repo.
briefing object none no Sources for the briefs the driver writes itself. Needed as soon as one PR's brief file does not exist. See briefing.sources.
policy object see below no Slots, the merge mode, approvals, attempts, timeouts and budgets. See policy.
prs list – at least one The PRs of the plan. See prs.

repo #

field type default required meaning
path path – yes Your local clone. The driver fetches there and adds the PR worktrees from it.
github string – yes owner/name on GitHub. Preflight fails unless the clone's origin is this repository on github.com. The driver passes it to every gh call as GH_REPO.
base string main no The branch every PR targets. After each merge the driver watches its checks and halts when they turn red.
public boolean true no true adds the public-repository rules to the prompts: no client names, no local paths. false drops them and keeps the denylist. It must be a boolean. Preflight fails for a public repo marked false and warns for a private one marked true.
pathPrepend list of paths [] no Directories that go first on PATH for the driver and every agent, for example a pinned node, pnpm or gh.
install command none no A shell command that runs in every new worktree through sh -c, with a 20 minute limit.
requiredChecks list of globs – yes, not empty Check run names a PR needs. Every glob must match a run that succeeded, and every run on the commit must finish as success, skipped or neutral. Only the latest run of each name counts.
agentToken path none no A file with the bot account's token. Agents get it as GH_TOKEN, and worktrees push over HTTPS with it. Without it agents act on GitHub as you, and preflight warns. policy.approval: github requires it. See Accounts.
maintainers list of logins [] no Whose reviews and comments count. Their GitHub review approves under approval: github, their review comments start fix runs, and a PR one of them authored merges with --admin under merge.admin: auto. With an empty list, review comments are ignored. The bot must not be on it.
pushUrl URL HTTPS URL of github no The push URL set on each worktree when agentToken is set. The default is https://github.com/<github>.git. The pre-push hook refuses every other URL, so your SSH key is never used for agent pushes.
merge object { method: squash, admin: auto } no method becomes --<method> on gh pr merge. Preflight checks the squash settings only for squash. admin: true always passes --admin, auto passes it only for a PR a maintainer authored, and false never does. Any value but false needs your gh login to be a repository admin, and preflight checks it.
neverMerge object the Changesets release PR no The release PR. The defaults are the branch glob changeset-release/* and the title chore: version packages. The gate blocks any PR whose head branch matches one of branches (globs) or whose title equals one of titles. When everything has merged, the driver finds the open release PR by title and tells you to merge it. Each key you set replaces its default list.
forbid list of globs [] no Paths no PR may touch. The implementer's prompt lists them, and a hit is a policy violation that goes back to the implementer.
alwaysInScope list of globs .changeset/*.md no Paths that never count as out of scope, whatever the PR's scope says.
denylist list of strings [] no Terms that must never appear: client names, local paths. The gate checks file paths, added lines, the PR title and body and commit messages, case-insensitively. A hit is a policy violation. The prompts name the terms too.
codeScanning object { action: fix, minSeverity: medium } no What new code scanning alerts on a PR do. The driver reads them from the code scanning API, before the verifier starts and again in the merge gate. An alert is new when it is open on the PR head and not open on the base.
  • action: fix sends the PR back to the implementer with every alert.
  • action: block blocks the PR until you dismiss the alert or send a note.
  • action: ignore makes no code scanning calls at all.
minSeverity is low, medium, high or critical. An alert counts at or above it. Its level is the security severity, otherwise error counts as medium and warning as low, and note never counts. An alert from an analysis of an older commit makes the driver wait for the head. A repo without code scanning is logged once per PR and goes on.
verify object {} no The verification recipe that the implementer and the verifier run, in order.
  • common: a list of commands for every PR.
  • smoke: one command, added for a PR with smoke: true.
  • viewer: a list, added for a PR with viewer: true.
The PR's extra steps come last. The verifier's copy of common drops commands that rewrite files: lint:fix, --fix, --write, a format script run with npm, pnpm, yarn or bun, and an install with any of them without --frozen-lockfile or --immutable. npm ci stays.

briefing.sources #

A PR whose brief file does not exist gets one from the driver, once its dependencies have merged. A read-only writer drafts it from these sources and a read-only reviewer checks it against the code. Without sources, the manifest fails to load as soon as one brief is missing.

field type default required meaning
title string the path no The heading of this source in the writer's and the reviewer's prompt.
path path – yes The file. Only a leading ~ expands, so a relative path resolves against the directory you started the driver in, not the rollout directory. A missing file is an error for every brief that needs it.
kind markdown or transcript markdown no transcript reads a Claude Code session log (JSONL) and keeps the last assistant text longer than 200 characters, such as design notes worked out in a chat. Anything else is read as plain text.
tag string none no A tagged source goes only to PRs that list the tag in briefTags. Untagged sources go to every PR.

policy #

Every key is optional. The nested objects merge key by key, so attempts: { fix: 6 } keeps the other defaults.

field type default meaning
concurrency number 2 Agents that run at once. A brief, writer and reviewer together, takes one slot, and so does a verifier. Gate checks, rebases and merges take none.
merge human, manual or auto human
  • human: the driver merges after your approval and mergeDelaySeconds.
  • manual: the driver verifies, gates and rebases, then notifies "ready to merge". You merge on GitHub and it carries on from there.
  • auto: the driver merges without an approval. Preflight warns.
approval inbox or github inbox How your approval reaches the gate under merge: human. inbox means rollout approve. github means a maintainer's review on GitHub for PRs the bot opened. PRs a maintainer authored still use rollout approve, because GitHub does not let authors approve their own PR. github needs repo.agentToken and repo.maintainers.
maxBump patch, minor or major minor The highest changeset bump allowed. A PR's changeset above it fails validation, and a changeset file above it is a policy violation.
attempts object implement 2, fix 4, verify 3, brief 2 Runs per role before the PR becomes escalated and waits for you. The verify count starts over once the PR is verified.
timeouts object, minutes implement 240, fix 90, verify 60, brief 60, delegate 30 The hard limit of one run of that role, in awake minutes: time the machine slept does not count. For a brief, the writer and the reviewer each get it.
stallMinutes number 20 An agent that prints nothing for this many awake minutes is stopped.
ciStallMinutes number 20 CI on a claimed commit still pending after this long sends the PR back to the implementer, with the missing and running checks.
budgetUsd object, USD per effort low 3, medium 8, high 20, xhigh 35, max 60 The cap of one run at that effort, passed as --max-budget-usd. A raised effort gets its own cap. There is no cap for a PR or the whole rollout.
tickSeconds number 60 The pause between ticks. A new command in the inbox wakes the driver sooner. A gap more than a minute longer counts as sleep.
mergeDelaySeconds number 120 Under merge: human, the wait before a merge. It runs from when the driver first sees an approval, and gives you time to notice an approval you did not expect and pause.
feedbackQuietMinutes number 3 How long a maintainer's last review comment must be quiet before the driver starts a fix run for it, so a review made of several comments becomes one fix run.
delegate mapping or null off Turns on the delegate, a read-only agent that answers a blocked PR from the plan or passes the question to you. {} turns it on with the defaults. kinds lists the questions it may answer ([brief-questions, needs-decision]), out of brief-questions, needs-decision, brief-contradiction and stuck. ci, environment, closed, gate and code-scanning are never delegated. maxPerPr caps its runs for one PR (2), and effort sets its effort (high).

prs #

One entry per PR. Their order breaks ties between equal priorities. Ids and branches must be unique, dependencies must name known PRs, and a cycle fails validation.

field type default required meaning
id string – yes, unique The short name you use in commands, like P1. It also names the worktree and the log files.
branch string – yes, unique The PR's branch. It is the only branch its agents may push to.
title string – yes The PR title. The merge commit's subject is the PR's title on GitHub plus (#N), with an empty body.
brief path – yes The brief, relative to the rollout directory. When the file does not exist, the driver writes it from briefing.sources once the dependencies have merged.
deps list of ids [] no PRs that must merge first. Work starts when they have merged, and the gate waits for them. A dependency left out by --only counts once GitHub shows its branch merged into the base with the rollout label.
priority number 0 no Higher goes first, for free slots and for merges.
effort object brief xhigh implement and verify One of low, medium, high, xhigh or max per role.
  • implement is used by the implementer and the fix runs. Each implement attempt after the first runs one level higher than the one before.
  • Fix runs rise one level per run from the third fix attempt on.
  • verify stays fixed.
  • brief is for the brief writer and the reviewer.
changeset patch, minor, major or none – yes The bump of the changeset this PR must add, never above policy.maxBump. none is for a repo without changesets: none is written and none is required.
scope list of globs [] no The files this PR is expected to change. When empty, the expected files of a brief the driver wrote are used. Files outside the scope and repo.alwaysInScope do not block the PR. They are listed on the card and the PR page for your review.
extra list of commands [] no Verification steps for this PR only, run after the repository's recipe.
expect list of strings [] no Expected results, like pnpm test: 214 passed. The implementer and the verifier compare their runs of the recipe with them. Without any, the expectation is "everything green".
smoke boolean false no Adds repo.verify.smoke to this PR's recipe.
viewer boolean false no Adds repo.verify.viewer to this PR's recipe.
allowWorkflows boolean false no Lets the PR change files under .github/. Without it, any such file is a policy violation. Changed workflow files are flagged on the card, so you review them before you approve.
briefTags list of strings none no The tags of the briefing sources this PR's brief writer gets, on top of the untagged ones.

What loading checks #

Every command except ui and help loads the manifest first and stops with invalid manifest and a list when any of these fails:

  • The manifest is a mapping, and so is every entry of prs.
  • rollout, repo.path, repo.github and at least one PR are there.
  • repo.requiredChecks is a list that is not empty.
  • policy.merge and policy.approval have known values, and approval: github has a token and maintainers.
  • repo.public, when set, is a boolean.
  • Every PR has an id, a branch, a title and a brief, ids and branches are unique, and both required efforts are known levels. effort.brief, when set, is a known level too.
  • Every changeset is a known bump or none, and none is above policy.maxBump.
  • deps is a list, every dependency names a known PR, and there is no cycle.

Loading also fails when a brief file is missing and there are no briefing sources, and when --only names an unknown PR.

Gotchas #

  • Edits apply on the next tick. A running driver reloads manifest.yaml when the file changes, without a restart and without stopping its agents. An edit that does not validate is reported as manifest-rejected and the driver keeps the previous manifest. A briefing source is read again when its size or modification time changes, so an edited plan or design note reaches the next brief without a restart.
  • Source paths are not relative to the rollout. A briefing.sources[].path without ~ or a leading / resolves against the directory you ran rollout run in. Brief paths do resolve against the rollout directory.
  • Briefs are written at xhigh. effort.brief defaults to xhigh for both the writer and the reviewer.
  • expect and extra go into the prompts. extra steps join the verification recipe both agents run. expect is the list of results they compare against. Neither is checked by the gate: the gate reads CI.
  • The example is not the defaults. examples/manifest.yaml sets concurrency: 3, merge: manual, approval: github and longer fix and verify timeouts. The defaults are in the tables above.

The rollout directory #

A rollout lives outside any repository, in $ROLLOUT_ROOT/<name>/, by default ~/.rollouts/<name>/. You write the manifest and, if you like, the briefs. The rest is written for you.

file written by meaning
manifest.yaml you The plan as PRs, described on this page.
briefs/<id>.md you or the driver One brief per PR. The only description of the work an implementer sees. It may name clients, so it stays local.
briefs/<id>.review-notes.md driver The brief reviewer's notes, next to a brief the driver wrote.
ledger.json driver The state of every PR and of the rollout (paused, halted, last merge). Written to a temp file and renamed, so it is never half written.
events.jsonl driver One JSON line per event: runs, gate decisions, merges, errors, rejected commands.
heartbeat driver The time and a note of the driver's last sign of life, written on every tick and every save.
driver.lock driver The pid of the running driver. A second driver refuses to start, and stop signals this pid.
inbox/ the CLI and the UI Commands waiting for the driver, one small JSON file each. Deleted once the driver reads them.
logs/<id>-<NN>-<role>.jsonl driver The stream-json transcript of each agent run. NN is the sum of the PR's attempt counters, or the brief attempt for a brief run, and a name already taken gets a -2 suffix. Brief runs have brief-write and brief-review as the role.
driver.log UI The output of a driver the UI started. A driver you start yourself prints to its terminal instead.
.gh-agents/ driver, preflight An empty gh config directory for the agents, so gh finds no stored login in it. Agents never get GH_HOST, which would make gh read your keyring login anyway.
.npmrc-agents driver An npm config without credentials for the agents.

The worktrees live next to the rollout, not inside it, so agents work nowhere near the ledger, the inbox or the manifest. Each PR gets <name>.worktrees/<id>/, a git worktree of repo.path on the PR's branch. Its git hooks point at the skill's git-hooks/, and with a token its push URL is repo.pushUrl. After the merge the driver removes the worktree, the local branch and the remote branch.
